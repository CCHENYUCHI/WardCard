## 1. 需求

使用者原話：「幫我目前的字典加上字根字首的功能，以及記憶學習的方法。」

拆成兩塊：

1. **字根字首**：查一個西語單字時，告訴使用者它由哪些字首 / 字根 / 字尾組成、各自的意思，以及同一個字根的其他單字（字族）。另外提供一個可以瀏覽常見字首、字尾、字根的頁面。
2. **記憶學習法**：幫使用者把單字記住的方法，包括字根拆解、英文同源字、假朋友（false friends）提醒、自己寫的記憶口訣，以及按下按鈕才呼叫的 AI 記憶法。

## 2. 雲端環境要先知道的事（重要）

### 2.1 `data/` 不在 Git 裡
`data/` 被 `.gitignore` 排除，所以雲端**沒有**：
- `data/dict/es-en.sqlite`：離線西英字典，約 90MB，約 80 萬筆。
- `data/wordcard.db`：使用者資料庫。伺服器啟動時會自動建立空的資料庫。

**影響**：
- 單元測試**不需要**真的字典檔。`server/dictionary.test.js` 的做法是用 fixture 建一個暫存字典，再呼叫 `setDictionary(db)` 注入。新功能的測試請沿用這個模式。
- 少了字典檔，`lookupForm()` 會回傳空陣列，`getDict()` 回傳 `null`。新程式碼也必須能在**沒有字典檔**的情況下正常運作：用策展表（curated list）降級，不能報錯。
- 如果雲端可以連外網、想做端到端測試，可以自己建字典（約 1GB 下載）：
  ```bash
  curl -L -o /tmp/es.jsonl https://kaikki.org/dictionary/Spanish/kaikki.org-dictionary-Spanish.jsonl
  npm run build:dict -- /tmp/es.jsonl
  ```

### 2.2 本機另一個分支還沒推上 GitHub
本機正在做 `feature/lookup-history`（查詢紀錄），還**沒有 commit / push**。這個分支修改了：
`server/index.js`（`/api/dictionary/lookup` 寫入紀錄，以及 `/api/dictionary/history` 三支 API）、`server/db.js`、`server/lookupHistory.js`（新檔）、`client/src/components/WordLookupPanel.jsx`、`client/src/utils/dictionary.js`、`client/src/components/TappableSentence.jsx`。

**為了讓之後合併容易**：
- 新邏輯盡量放在**新檔案**。
- 對 `server/index.js`、`WordLookupPanel.jsx`、`utils/dictionary.js` 的修改**只用新增的方式**（加 import、加新路由、加一個區塊），不要重排或改寫既有程式碼。
- `/api/dictionary/lookup` 的 handler 只在 `res.json({...})` 裡多加一個欄位，其餘不動。

### 2.3 其他限制
- **只做 Web**（`client/`）。使用者用手機 Safari 開網頁版，不動 `mobile/`。
- UI 跟著實際程式碼的**淺色 Google / Material 風格**（`index.css` 的 `--google-*` 變數、`.surface-card`），**不是** AGENTS.md 寫的 Dark Glassmorphism。
- **省額度**：能用本機邏輯做到的就不用 AI；AI 只在使用者按下按鈕時呼叫，用 flash-lite，結果永久快取並讓所有使用者共用。
- 後端記憶體約 35MB：不要在啟動時把整本字典或大表載入記憶體；策展表是小型 JS 常數，沒有問題。
- 雲端大概沒有 Gemini Key：AI 的部分用單元測試（stub `callGemini` 或只測 normalize 函式）驗證。
- Node 22+，用內建 `node:sqlite` 和 `node:test`，**不要裝新套件**。

## 3. 目前字典的現況

### 3.1 查詞順序（便宜的在前面）
1. **離線 Wiktionary**（`lookupForm`）：把變化形還原成原形（`fui` → ir / ser），提供英文釋義和陰陽性；查不分重音，但完全相同的拼法排前面（`año` 排在 `ano` 前）。
2. **我的單字庫**（`findMyCards`）：用原形比對自己的卡，支援 `bonito/a`、`niño(a)`、反身動詞 `-se`；輸入中文時改搜中文釋義。
3. **共用快取**：`sentence_analyses`（整句逐字解析）、`dictionary_cache`（AI 字典詞條）。
4. **AI（只在按下按鈕時）**：「✨ AI 解析這句」、「用 AI 查中文」，用 flash-lite，失敗才換主模型。

## 4. 建議設計

### Phase A：字根字首（不用 AI）

**A1. 策展表 `server/data/morphemes.js`**（新檔，純資料）
```js
// type: 'prefix' | 'suffix' | 'root'
{ id: 'des', type: 'prefix', forms: ['des', 'de'], meaning_zh: '否定、相反、去除', english: 'un-, dis-',
  examples: [{ word: 'deshacer', base: 'hacer', zh: '拆開、解開' }, ...] }
```
- 數量大約：字首 35–45 個（a-, ante-, anti-, auto-, bi-, co(n)-, contra-, de(s)-, en/em-, entre-, ex-, extra-, hiper-, in/im/i-, inter-, mal-, multi-, pre-, re-, sobre-, sub-, super-, tele-, trans-, tri-, uni-…）。
- 字尾 45–55 個，加上 `pos_from` / `pos_to` 和拼字變化規則，例如：-ción/-ación/-ición、-dad/-idad/-tad、-mente、-oso/a、-ble/-able/-ible、-ero/a、-ería、-ista、-ismo、-ito/-cito/-ecito、-ón、-azo、-al、-ivo、-dor/a、-miento、-anza、-ura、-ez(a)、-izar、-ificar…。
- 字根 40–60 個（拉丁 / 希臘），例如：port（搬運）、dic/dict（說）、scrib/scrit（寫）、vid/vis（看）、duc（引導）、mit/mis（送）、pon/pos（放）、tra(c)/trah（拉）、cred（相信）、fac/fec/hac（做）、bio、geo、grafo、logo、fono、tele、crono…。
- 每個項目要有 `meaning_zh`、`english`（英文對應），以及 2–4 個 `examples`。

**A2. `server/morphology.js`**（新檔）
- `analyzeWord(lemma, { dict })` → `{ parts: [{ text, type, id, meaning_zh }], base, family_hint, confidence: 'verified' | 'pattern' }`
  - 規則：先試字首 + 基底、再試基底 + 字尾（處理拼字變化：z→c、-mente 接陰性形、-ción ← -ar/-er/-ir 動詞、去掉字尾母音再接 -ería / -ero / -ito），組合起來最多兩層。
  - 拆出來的基底在離線字典查得到原形（`glosses != '[]'`），就標成 `verified`。
  - 沒有字典時，只用策展表的 `examples` 精確比對（`verified`），或用最長字首 / 字尾比對（`pattern`，前端顯示「可能」）。
  - **避免誤拆**：基底至少 3 個字母；`re-` / `in-` 這類短字首一定要驗證基底存在才採用（例如 `real` ≠ re + al、`interés` 不是 inter- + és）。可以準備一份小型排除清單。
- `wordFamily(base, { dict, limit: 12 })`：用字首 × 基底、基底詞幹 × 字尾產生候選字，再用 `word_norm = ?` 逐一驗證（每次查詢只走索引，候選數有上限）；也可以加上 `word_norm LIKE 'stem%'`（有索引）。
- `findMorpheme(id)` / `listMorphemes({ type, q })`：給瀏覽頁使用。

**A3. API**
- `GET /api/dictionary/lookup` 的回應**多加** `morphology: analyzeWord(lemma)` 一個欄位，其餘不動（見 §2.2）。
- `GET /api/morphemes?type=&q=`：列表。
- `GET /api/morphemes/:id`：詳情，回傳策展範例 + 字典裡找到的字族 + 我的單字庫裡含這個字根的卡（`findMyCards` 或 `word LIKE`，限定自己的 user_id）。

**A4. 前端**
- `WordLookupPanel.jsx`：在 Wiktionary 區塊上方插入新元件 `<MorphologyBreakdown data={result.morphology} />`（新檔）。用彩色小方塊顯示 `des | hacer`，點每一塊可以看意思，點字族裡的字會重新查詞（字典頁才有；點字視窗 `compact` 時只顯示拆解、不顯示字族）。
- `DictionaryView.jsx`：頂部加上 segmented 切換「查詞 | 字根字首」。新檔 `MorphemeBrowser.jsx` 分成字首 / 字尾 / 字根三組，可以搜尋；點進去顯示意思、英文對應、範例（每個字都有 🔊，點字會跳到查詞）、「你的單字庫裡有 N 個」。

### Phase B：記憶學習法

**B1. 英文同源字與假朋友（不用 AI）**：新檔 `server/cognates.js`
- 用字尾對應規則把西語字轉成英文候選：-ción→-tion、-sión→-sion、-dad/-tad→-ty、-mente→-ly、-oso→-ous、-ble→-ble、-ista→-ist、-ismo→-ism、-ico→-ic、-ario→-ary、-ente/-ante→-ent/-ant、-ivo→-ive、-al→-al、-izar→-ize、-ificar→-ify，以及字首 es+子音 → s+子音（escuela→school、estudiar→study）。
- 和 Wiktionary 英文釋義比對（去重音後的編輯距離或前綴相似度），相似就回傳 `{ english, kind: 'cognate' }`。
- **假朋友表**（約 30–50 筆，策展）：embarazada、éxito、librería、carpeta、constipado、actual、sensible、asistir、realizar、molestar、ropa、fábrica、largo、recordar、soportar…，回傳 `{ looks_like, actual_zh, kind: 'false_friend' }`，前端用警告色顯示。
- 放進 lookup 回應：`memory: { cognate, false_friend }`，和 `morphology` 一樣只新增欄位。

**B2. 自己的記憶口訣（卡片欄位）**
- `cards.mnemonic TEXT DEFAULT ''`，用 `runMigrations()` 的 `try { ALTER TABLE } catch {}` 寫法遷移。
- `POST /api/cards`、`PUT /api/cards/:id`、CSV / JSON 備份還原都要帶上這個欄位（先 grep 看還原邏輯怎麼處理欄位）。
- `WordModal.jsx`（編輯）加一個 textarea「🧠 記憶口訣」；`WordDetailModal.jsx` 顯示這個欄位；`WordLookupPanel` 的「我的單字」列有口訣時也顯示。
- `AdaptiveStudySession.jsx`：**只在翻面後 / 作答後**顯示口訣（S1/S2 翻面後，S3–S5 答完後），不能在作答前洩漏答案。這個檔案很大，只插入顯示區塊就好。

**B3. AI 記憶法（按鈕觸發，共用快取）**
- 新表 `mnemonic_cache(query_norm TEXT PRIMARY KEY, result TEXT NOT NULL, model TEXT, created_at ...)`，不綁使用者與卡片，刪卡不需清理。
- `server/ai.js` 新增 `generateMnemonic({ apiKey, word, morphology, glosses })`：用 flash-lite（沿用 `lookupWordAi` 的模型選擇方式），responseSchema 回傳
  `{ breakdown_zh, cognate_en, keyword_zh（諧音或關鍵字聯想）, story_zh（1–2 句畫面感的聯想）, example_es, example_zh }`。
  Prompt 帶入本機已經算好的 morphology 和英文釋義，讓 AI 少猜一點，也少用一些 token。
- 新增 `normalizeMnemonic()`：截斷長度、補上預設值、內容不完整時丟出錯誤（參考 `normalizeTranslation` 和 `server/translations.test.js`）。
- `POST /api/dictionary/mnemonic` `{ q }`：先查快取（原形和變化形各存一筆，跟 `/api/dictionary/ai` 一樣），沒有才呼叫 AI；沒有 Key 時回 `NO_KEY_ERROR`。
- 前端：在 `WordLookupPanel`（非 compact）加「🧠 AI 記憶法」按鈕；結果卡片附「存成我的口訣」，如果使用者已經有這張卡，就 `PUT` 寫入 `mnemonic`。

**B4. 記憶方法說明**：`MorphemeBrowser` 頂部加一張可以收合的說明卡，介紹字根拆解、英文同源、小心假朋友、關鍵字聯想、自己造句，並說明 FSRS 會自動安排複習時間。文字簡短就好。
